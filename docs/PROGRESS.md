### File 06 decisions & notes
- **`withCreditGate(userId, action, refId, fn)`** (on `BillingService`, `@extrovertai/server`) is **THE MANDATORY PATH** for every paid external action (Files 07/08/09/10). It reserves → runs `fn` → commits on success / refunds on failure. `InsufficientCreditsError` is thrown BEFORE `fn` runs when the user can't afford it. No paid external call may bypass it.
- **Atomicity/race-safety** lives in Postgres functions (migration `20260607020000_credit_functions.sql`): `reserve_credits` takes a per-user `pg_advisory_xact_lock`, checks `sum(delta)`, then debits + writes a `reserved` usage_event — so two concurrent reserves can't both pass on a 1-credit balance (verified). `refund_usage` is idempotent (no double-credit). Balance is **always** `sum(credit_ledger.delta)` — never stored.
- **Security:** these functions are `revoke execute ... from public` + `grant execute ... to service_role`, so only the backend can mint/reserve/refund — never the anon/authenticated API roles. Function signatures were added to the generated `Database` type for typed `.rpc()`.
- **BullMQ on Upstash:** connection built from `REDIS_URL` and passed to BullMQ as **options** (host/port/password/tls parsed from the URL) so BullMQ uses its own bundled ioredis (avoids cross-copy ioredis type/instance conflicts). `maxRetriesPerRequest:null` set. BullMQ 5 supports rate-limiting + delayed jobs (needed for throttled sending in File 10). `metering-test` queue + worker prove the gate end-to-end; real queues are added per-file.
- **Redis verified** (PONG + set/get over rediss:// TLS). The File 01 worker "REDIS_URL absent" warning path is now the real connection.
- Credit costs are still the File-01 placeholders (`search/enrichment/draft/send` = 1 each); finalized in File 14.

### File 08 decisions & notes
- **Credit unit: 1 credit per LEAD enrichment** (`CREDIT_COSTS.enrichment`), NOT per paid sub-call. The whole per-lead pipeline (Place details + crawl + LLM) runs inside ONE `withCreditGate(userId, 'enrichment', leadId, fn)`. Inside `fn`, each external step is individually try/caught so a single failure becomes an honest "not found" (partial result) and still commits — only a truly unexpected error throws → gate refunds (net-zero). Verified live: −1 credit per lead.
- **Bulk = one BullMQ job per lead** (`ENRICHMENT_QUEUE`, payload `{userId, leadId}`) so progress is per-lead and one failure never fails the batch. Worker consumer concurrency = 3 (polite to Places/Firecrawl/OpenRouter). The api is the **producer** (added `bullmq` dep to `apps/api`); the worker is the **consumer**. Shared `buildRedisConnection` util in `@extrovertai/server`.
- **enrichment_status mapping:** existing DB enum is `pending|in_progress|complete|failed` (no `partial` value). Used as coarse progress: `pending`=queued, `in_progress`=running, `complete`=done (full OR partial), `failed`=error. **No "partial" enum value added** (avoided a risky `alter type` migration); partial-ness is surfaced from the DATA instead (email null → UI shows "No email found"). Idempotent: a lead already `complete` is **skipped without re-charge** (verified delta 0).
- **Reviews via Place Details (New)** `GET /v1/places/{id}` with field mask `id,reviews,websiteUri,nationalPhoneNumber,internationalPhoneNumber,rating,userRatingCount` (paid details/reviews SKU; up to 5 reviews). **Cached GLOBALLY by `places:details:{placeId}` (TTL 30d)** in `EnrichmentService` (place data is the same for everyone — global cache cuts cost; the per-lead enrichment credit still applies). Cache write only on `status==='ok'`.
- **One LLM call** does BOTH the review positive/negative split AND the hook (returns `{positive[], negative[], hook}`) — halves model load (free models are rate-limited per File 05). **Deterministic fallbacks** if the LLM is unavailable: `heuristicSplit` (by star rating) + a grounded `fallbackHook` (no-website → "pitch a simple site"; low rating → reputation angle; else neutral). Never fabricates.
- **Email ranking** (`contact-extract.ts`, pure/unit-tested): crawl homepage then up to 2 likely contact pages (`/contact`, `/about`), stop once an email is found (saves crawl calls). Filters image-traps (`.png` etc.), placeholder domains (`example.com`…), hash-like locals. Scores: +site-domain match, +person/role, −generic (`info@`…), −`noreply@`; `noreply` is NEVER `best` (alternates only). **Alternates are NOT persisted** (no `leads` column for them) — only `leads.email` (best) is stored; future migration could add `email_alternates`.
- **Phone:** prefers the Places phone already on the lead, else first plausible site-extracted number (7–15 digits).
- **No finder-API fallback wired** — no finder key in `.env`; the slot is documented in code (extend `readSiteForContacts`/add a metered provider later). On-site extraction only for MVP.
- **Out-of-credits:** api does an **upfront balance check** and enqueues only what the user can afford, returning `{enqueued, skipped, reason:'partial_credits'|'out_of_credits'}` so leads are never silently dropped; the worker's gate is the final race safety net. Web shows a clear top-up prompt.

Populated-card visual was NOT screenshotted (the browser Supabase session had expired); the `/enrich` screen empty/picker state WAS screenshotted and renders correctly (calm UI, teal accent, honest copy, no purple/gradients). Card rendering is covered by the build + the live data shape.
